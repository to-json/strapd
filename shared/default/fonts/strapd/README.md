# strapd icon font

The private-use glyphs in `strapd.ttf` are:

- `U+E900`: strapd's own mark, traced from `default/plymouth/logo.png`. Jae drew both; `strapd-mark.svg` beside this file is the traced source
- `U+E901`: Pi, from <https://pi.dev/logo-auto.svg>
- `U+E902`: OpenCode, from <https://opencode.ai/favicon-96x96-v3.png>
- `U+E903`: omp, from <https://omp.sh/favicon.svg>
- `U+E905`: Codex, from the OpenAI mark on <https://developers.openai.com/codex/>
- `U+E906`: LM Studio, from <https://simpleicons.org/icons/lmstudio.svg>
- `U+E907`: Ollama, from <https://simpleicons.org/icons/ollama.svg>
- `U+E908`: T3 Code, traced from the app icon in <https://aur.archlinux.org/cgit/aur.git/plain/t3code-icon.png?h=t3code-bin>, since upstream publishes no monochrome SVG
- `U+E909`: Ori, from <https://openrouter.ai/brand/v2/openrouter-glyph-dark.svg>, OpenRouter's own mark. Ori ships no separate logo and its product page uses this one

The agent marks are monochrome so the menu can render them in the active theme's
foreground and selection colors.

The font's family name is `strapd`, and that's what a menu entry's `iconFont`
matches on. It lives inside the .ttf rather than in its path, so a font
regenerated by Fontello needs `strapd dev font family --set strapd` before
anything will find it.

`U+E900` held upstream's logo, which came over with the port inside a binary
neither rename pass could see. Someone else's mark is not ours to ship whatever
the file is called, so the slot sat empty until strapd had one of its own. It
now carries the belt-and-buckle mark, traced from the plymouth logo by whole
pixel boundaries, so the glyph is exactly the artwork rather than an
approximation of it.
